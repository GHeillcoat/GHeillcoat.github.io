## 概述

推理模型 (Reasoning Models) 是 2024-2026 年间 LLM 领域最重要的范式创新。与传统 LLM 直接生成答案不同，推理模型在生成最终答案之前会先进行**显式的、可解释的链式推理 (Chain-of-Thought)**，模拟人类"先思考，再回答"的认知过程。这一范式的核心突破在于：**将推理时的计算资源 (Test-Time Compute) 作为可扩展的维度**，通过增加推理时间来提高答案质量，而不需要增大模型参数。

2025 年被广泛认为是"推理模型元年"，而到 2026 年，推理模型已成为所有主流 LLM 提供商的标配能力。

## 什么是推理模型

### 传统 LLM 的工作方式

```
用户: "一个农场有 15 只鸡和 8 只兔子，一共有多少条腿？"
    ↓
LLM 直接生成: "一共有 62 条腿。"
    ↓
（可能正确，也可能错误，没有中间推理过程）
```

### 推理模型的工作方式

```
用户: "一个农场有 15 只鸡和 8 只兔子，一共有多少条腿？"
    ↓
推理模型内部思考:
  "我需要计算鸡和兔子的腿的总数。
   鸡有 2 条腿，15 只鸡 = 15 × 2 = 30 条腿。
   兔子有 4 条腿，8 只兔子 = 8 × 4 = 32 条腿。
   总数 = 30 + 32 = 62 条腿。
   让我验证一下... 15×2=30, 8×4=32, 30+32=62。正确。"
    ↓
输出: "一共有 62 条腿。"
```

### 关键特征

| 特征 | 传统 LLM | 推理模型 |
|------|----------|----------|
| 推理过程 | 隐式（在参数中） | 显式（可见的思维链） |
| 推理深度 | 浅（单步或少量步骤） | 深（多步、迭代、自我修正） |
| 可解释性 | 低 | 高（可查看推理过程） |
| 推理时间 | 固定（与输入长度相关） | 可变（模型自主决定思考时间） |
| 计算分配 | 全部在训练阶段 | 训练+推理时动态分配 |
| 数学能力 | 有限 | 显著提升（GSM8K 95%+） |
| 编码能力 | 有限 | 显著提升（Codeforces 1800+） |
| 幻觉率 | 较高 | 较低（推理过程自我验证） |

## 推理模型 vs 标准 LLM 对比

| 维度 | 标准 LLM (GPT-4o, Claude) | 推理模型 (o4, R1) |
|------|--------------------------|-------------------|
| 推理方式 | 单次生成，隐式推理 | 多步推理，显式思维链 |
| 推理时间 | 固定 | 动态（简单问题快，复杂问题慢） |
| 数学 (GSM8K) | 90-92% | 96-98% |
| 编程 (Codeforces) | ~1200 rating | ~1800-2200 rating |
| 博士级科学 (GPQA Diamond) | 50-60% | 75-87% |
| 创意写作 | 优秀 | 一般（过度推理倾向） |
| 翻译 | 优秀 | 效率较低（不必要的推理） |
| 常识问答 | 优秀 | 可能过度思考 |
| 成本 (per token) | 较低 | 较高（推理 token 也被计费） |
| 适用场景 | 通用 | 数学、编程、科学、逻辑推理 |
| 不适用场景 | — | 创意写作、闲聊、翻译 |

## Test-Time Compute Scaling（推理时计算扩展）

这是推理模型的核心技术理念。传统 Scaling Laws 关注的是训练时计算（更大的模型 + 更多数据），而 Test-Time Compute Scaling 关注的是推理时计算。

### 推理时计算扩展的两种方式

```
方式 1: 并行采样 (Best-of-N / Majority Voting)
    ↓
    生成 N 个独立答案 → 投票/验证 → 选择最佳答案
    ↓
    优点: 简单，可并行
    缺点: 计算效率低，N 倍成本

方式 2: 顺序推理 (Chain-of-Thought / Tree-of-Thought)
    ↓
    生成推理链 → 自我验证 → 修正 → 继续推理 → 最终答案
    ↓
    优点: 计算效率高，可解释
    缺点: 不能并行，总延迟高
```

### 推理时计算扩展的 Scaling Law

2024-2025 年的研究表明，推理时计算也遵循可预测的 Scaling Law：

- 在固定模型大小下，增加推理时计算量（更多思考 token）可以持续提升性能
- 对于简单问题，推理时计算的边际收益递减很快
- 对于复杂问题，推理时计算可以带来指数级提升
- 存在一个最优的"推理时计算预算"分配策略

## GRPO：推理模型的核心训练算法

GRPO (Group Relative Policy Optimization) 是 DeepSeek-R1 使用的强化学习算法，是推理模型训练的关键技术突破。

### GRPO 的核心流程

```
1. 对于一个查询，生成 G 个候选答案（一个 Group）
2. 对每个答案计算奖励 (Reward)：
   - 准确性奖励：答案是否正确
   - 格式奖励：推理格式是否符合要求
   - 语言一致性奖励：是否保持目标语言
3. 用组内相对优势 (Group Relative Advantage) 代替绝对奖励
4. 更新策略（模型参数），使模型偏向生成高奖励的答案
```

### GRPO vs PPO vs DPO 对比

| 维度 | PPO | DPO | GRPO |
|------|-----|-----|------|
| 是否需要参考模型 | 是 | 是 | 否 |
| 是否需要价值模型 (Critic) | 是 | 否 | 否 |
| 训练稳定性 | 中等 | 高 | 高 |
| 计算效率 | 低 | 高 | 最高 |
| 推理能力涌现 | 弱 | 弱 | 强 |
| 代表应用 | InstructGPT | Llama 3, Qwen2 | DeepSeek-R1, 多数推理模型 |

## 2025-2026：定义性的模型趋势

### 推理模型改变了一切

1. **能力边界被打破**：推理模型在数学竞赛 (IMO)、编程竞赛 (IOI)、博士级科学问题上超越了人类专家水平。

2. **推理时计算成为新维度**：模型能力不再只由参数数量决定，推理时的计算预算成为同等重要的维度。

3. **开源推理模型崛起**：DeepSeek-R1 的开源引发了全球推理模型的开源浪潮，Qwen3-Thinking、Llama-4-Reasoning 等相继发布。

4. **推理成本下降**：从 o1 的 $60/1M tokens 到 R1 的 $2.19/1M tokens，再到蒸馏模型的 $0.14/1M tokens，推理模型的成本在一年内下降了两个数量级。

5. **多模态推理**：推理能力从文本扩展到图像、视频、音频，实现跨模态推理。

6. **Agent 推理**：推理模型与 Agent 框架结合，使 Agent 能够进行复杂的多步规划和推理。

7. **推理模型的人机协作**：人类可以查看和干预模型的推理过程，实现真正的协作推理。

### 推理模型的局限

- **过度推理 (Overthinking)**：对简单问题进行不必要的深度推理
- **推理语言切换**：非英语查询时，模型可能在推理过程中切换到英语
- **奖励黑客 (Reward Hacking)**：模型可能学会利用奖励函数的漏洞
- **推理幻觉**：推理过程本身可能包含错误推理，但最终答案恰好正确
- **成本**：推理 token 使每次查询的成本显著增加
