Agent 调用工具不是"想调就调"——有几种不同的设计模式：

| 模式 | 怎么工作 | 优点 | 缺点 |
|------|---------|------|------|
| ReAct | 交替推理和行动，每步想一次做一次 | 灵活、可解释 | 慢，简单任务也多想一步 |
| Plan-and-Execute | 先一次性规划全部步骤，再逐步执行 | 效率高，全局视角好 | 计划出错时难以中途调整 |
| Tool-use-only | 只在需要时调用工具，不显式推理 | 快，适合简单任务 | 复杂任务容易漏步骤 |
| Reflexion | 在 ReAct 基础上加了"事后反思"环节 | 能从错误中学习 | 增加推理成本 |

2026 年主流 Agent 框架（LangGraph、CrewAI）默认使用 ReAct 或变体，因为它的灵活性最高。Plan-and-Execute 在步骤可预测的场景（如定时报告生成）中更高效。
