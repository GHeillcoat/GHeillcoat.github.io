| 维度 | 用单 Agent | 用多 Agent |
|------|-----------|-----------|
| 任务复杂度 | 低-中，步骤少于 10 步 | 高，需要 10+ 步骤 |
| 可分解性 | 任务难以拆成独立子任务 | 任务天然可以拆成多个独立子任务 |
| 需要多视角 | 不需要，单一视角即可 | 需要不同专业视角（如法律+技术+业务） |
| 准确率要求 | 90% 以下可接受 | 需要 95%+，需要交叉验证 |
| 延迟要求 | 低延迟，5-15 秒完成 | 可接受 30-120 秒 |
| 成本预算 | 低，单次任务 $0.1-$1 | 高，单次任务 $1-$10 |
| 开发复杂度 | 低，一个 prompt+几个工具 | 高，需要设计 Agent 角色、通信、协调 |
| 维护成本 | 低，调一个 Agent 即可 | 高，每个 Agent 独立维护 |
| 错误容忍度 | 有一定容忍度，错了重来 | 零容忍，一个环节出错影响全局 |
| 典型场景 | 个人助手、简单搜索、格式转换 | 研究报告、代码审查、客服系统、医疗诊断 |

**决策法则**：先问自己两个问题——"这个任务能不能拆成 3 个以上互不依赖的子任务？"和"一个专家能不能独立完成？"如果第一个答案是"是"且第二个答案是"否"（需要多个专家），就用多 Agent。如果任务简单或一个人就能搞定，单 Agent 足够——多 Agent 的额外复杂度不值得。
