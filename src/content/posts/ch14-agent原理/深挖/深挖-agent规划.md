[[深挖-ReAct循环]] 里 Agent 是"走一步看一步"——每步根据当前观察决定下一步。这叫**反应式规划**。但有些任务需要在动手之前先想好整个路线图。这叫**前瞻式规划**。这篇对比两种思路，以及它们怎么混合使用。

## 反应式规划：ReAct 模式

**思路**：不想太远，只看下一步。

**优点**：灵活。上一步的结果不如预期，下一步马上调整。不会被一个错误的初始计划带偏。

**缺点**：短视。可能陷入局部最优——搜了三轮发现方向就错了，但已经浪费了时间和钱。

**适合**：信息不确定的任务。你不知道搜出来是什么，只能查一步看一步。

## 前瞻式规划：Plan-and-Execute

**思路**：先列好完整计划，再一步步执行。

例子：用户说"帮我写一份关于 2024 年 AI 行业融资的报告"

```
Plan:
Step 1: 搜索"2024年AI行业融资总额"
Step 2: 搜索"2024年AI领域最大10笔融资"
Step 3: 搜索"2024年AI融资趋势分析"
Step 4: 整理数据，按金额排序
Step 5: 写报告大纲
Step 6: 按大纲逐段写
```

然后按计划执行。执行过程中如果发现计划有问题（比如 Step 2 搜出来的结果太少），可以修改计划 ^[Wang et al., "Plan-and-Solve Prompting", 2023, https://arxiv.org/abs/2305.04091]。

**优点**：全局最优。动手前想清楚，不会走冤枉路。

**缺点**：僵硬。如果计划本身有错误（比如搜错了关键词），执行到一半才发现，前面几步就白费了。

**适合**：任务结构清晰、步骤可预知。比如写报告、做数据分析、代码重构。

## 混合规划：Plan + ReAct

最佳实践是两者结合——**先规划大方向，执行中灵活调整。**

2026 年主流 Agent 框架（LangGraph、AutoGen）的做法：

1. **先规划**：Agent 列出 3-5 个高层次步骤
2. **逐步执行**：每一步用 ReAct 模式（Thought -> Action -> Observation）灵活处理
3. **定期检查**：每完成 2-3 步，回到计划层面审视——后面的步骤还需要调整吗？
4. **动态修正**：如果发现计划不对，不从头开始，只修改后续步骤

这就是"宏观规划，微观反应"。

## 树搜索规划：思考多条路

前面的方法只走一条路。但如果 Agent 不确定哪条路更好呢？

**Tree-of-Thoughts（思维树）** ^[Yao et al., "Tree of Thoughts", 2023, https://arxiv.org/abs/2305.10601]：同时探索多条路径，每走一步评估每条路径的质量，淘汰差的，保留好的。像下棋——你不会只看一步，你会想"如果我走 A，对手走 B，我再走 C..."

代价极高——每条路径都要实际执行，费用翻好几倍。只在"怎么做都不确定"的高价值场景使用。

## 应用场景对比

| 规划方式 | 延迟 | 成本 | 灵活性 | 适合 |
|---------|------|------|--------|------|
| 纯 ReAct | 低 | 低 | 高 | 信息检索、简单问答 |
| Plan+Execute | 中 | 中 | 低 | 报告生成、代码重构 |
| Plan+ReAct | 中 | 中 | 高 | 复杂 Agent 任务 |
| Tree-of-Thoughts | 高 | 极高 | 极高 | 数学证明、策略决策 |

**2026 年默认选择**：Plan+ReAct。既有全局视图，又有局部灵活。
